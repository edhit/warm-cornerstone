# CODE-бот и деплой — запуск, остановка, автозапуск

Всё управление — через один скрипт `scripts/wake-bot.sh`. Запускайте
команды из корня проекта (`warm-cornerstone`).

## Быстрые команды

```bash
./scripts/wake-bot.sh          # запустить бота (если ещё не запущен) + деплой
./scripts/wake-bot.sh status   # посмотреть, работает ли бот сейчас
./scripts/wake-bot.sh stop     # остановить бота
./scripts/wake-bot.sh restart  # остановить и запустить заново (+ деплой)
```

Если скрипт ещё не исполняемый:
```bash
chmod +x scripts/wake-bot.sh
```

## Запуск

```bash
./scripts/wake-bot.sh
```

Что произойдёт:
- если бот уже работает — ничего не делает, просто пишет об этом в лог
- если не работает — запускает его в фоне (PID сохраняется в `bot/bot.pid`,
  вывод бота пишется в `bot/bot.log`)
- после этого в любом случае запускает `scripts/deploy-yandex.mjs`
  (вывод — в `scripts/deploy.log`)

Проверить, что бот правда поднялся:
```bash
./scripts/wake-bot.sh status
```
```
🟢 Бот работает, PID 493
  PID     ELAPSED COMMAND
  493       00:02 node /home/mgn/warm-cornerstone/bot/index.js
```

## Остановка

```bash
./scripts/wake-bot.sh stop
```

Скрипт сам найдёт процесс по `bot/bot.pid`, аккуратно остановит (сначала
обычным `kill`, через 5 секунд, если не отреагировал — принудительно),
удалит PID-файл. После этого `./scripts/wake-bot.sh status` покажет
🔴 Бот не запущен.

**Важно:** просто остановить процесс командой `stop` достаточно, только
если у вас не настроен автозапуск (разделы ниже) — иначе бот снова
поднимется при следующем включении ПК или выходе из сна. Если хотите
выключить бота насовсем, смотрите следующий раздел.

## Полностью выключить бота (включая автозапуск)

Если бот был подключён к автозапуску (по инструкции из
`scripts/README-autostart.md`), одной остановки процесса недостаточно —
нужно убрать оба триггера, иначе он поднимется сам:

**1. Остановить сам процесс:**
```bash
./scripts/wake-bot.sh stop
```

**2. Убрать автозапуск при включении ПК:**
```bash
crontab -e
```
Удалите (или закомментируйте символом `#` в начале) строку со
`wake-bot.sh`, сохраните и закройте редактор.

Проверить, что строки больше нет:
```bash
crontab -l | grep wake-bot
```
(если ничего не вывелось — всё чисто)

**3. Убрать хук на выход из сна:**
```bash
sudo rm /usr/lib/systemd/system-sleep/systemd-sleep-code-bot
```

После этих трёх шагов бот больше не запустится сам ни при включении ПК,
ни при выходе из сна — только вручную командой `./scripts/wake-bot.sh`.

## Логи — где что искать

| Файл                          | Что там                                  |
|-------------------------------|-------------------------------------------|
| `scripts/wake-bot.log`        | Что делал сам скрипт (запуск/пропуск/деплой) |
| `bot/bot.log`                 | Вывод самого Telegram-бота                |
| `scripts/deploy.log`          | Вывод `deploy-yandex.mjs`                 |
| `scripts/wake-bot-cron.log`   | Вывод при запуске через `@reboot` (если настроен) |

## Автозапуск (включение ПК / выход из сна)

Подробная инструкция по подключению — в `scripts/README-autostart.md`.
Коротко:
- включение ПК → строка `@reboot` в `crontab -e`
- выход из сна → хук `scripts/systemd-sleep-code-bot`, установленный в
  `/usr/lib/systemd/system-sleep/`

Оба триггера просто вызывают `wake-bot.sh` без аргументов — то есть ведут
себя как обычный запуск (проверяет, не работает ли уже, запускает при
необходимости, потом деплоит).
